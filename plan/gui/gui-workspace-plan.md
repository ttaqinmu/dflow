# GUI workspace refactor

## Context
DFlow currently has one `dflow` binary crate (`Cargo.toml`, `src/main.rs`). The requested outcome is a workspace with `dflow-core` library, `dflow-tui` library, `dflow-gui` library, and feature-selectable `dflow` binary. The GUI must present nodes, directed edges, colors and details, with zoom, pan and draggable nodes; `--render gui|tui` on existing comparison commands selects interactive output. The implementation must also commit this execution plan under `plan/gui/`; plan-mode writes may only use this session-local file until approval.

## Findings
- `src/cli.rs` exposes `local|branch --format json|mermaid|dot|tui`; `src/main.rs` resolves TUI only for terminal stdin+stdout, otherwise JSON. Keep JSON, Mermaid and DOT without either UI feature; user selected `--render gui|tui` rather than a new subcommand.
- `src/git/mod.rs::capture_comparison` and `src/report/mod.rs::AnalysisSession::report` depend on binary-owned `CompareMode`; core must own a CLI-independent comparison selection. `src/report/mod.rs::focused_graph` is the existing deduplicated graph, currently private to the binary. `src/diagram.rs` renders it.
- Existing TUI is `src/tui/{mod,state,layout,render,watch}.rs`. Local comparisons live-recapture with `notify`; branch comparisons stay fixed. Details in `state.rs::node_details` read captured base/target source and call sites. Binary integration tests use `CARGO_BIN_EXE_dflow`; source-level fixture inclusions occur in `src/analysis/mod.rs` and `src/languages/rust/mod.rs`.
- Selected stack: `egui_graphs 0.32` + `eframe 0.36` (matching `egui 0.36` and existing `petgraph 0.8`, [crate dependencies](https://docs.rs/crate/egui_graphs/0.32.0)). `GraphView` supports node dragging/selection and pan/zoom; a hierarchical layout is provided ([widget](https://docs.rs/egui_graphs/latest/egui_graphs/struct.GraphView.html), [navigation](https://docs.rs/egui_graphs/latest/egui_graphs/struct.SettingsNavigation.html)).

## Approach
### 0. Preserve requested plan artifact
Before source edits, copy this approved plan into `plan/gui/gui-workspace-plan.md`, retaining its steps and chosen versions. The session-local approval artifact is not a substitute for the requested project file. Revise `plan/README.md` and `plan/06-mermaid-and-zed.md` only where their single-crate prohibition contradicts the new workspace; Zed implementation remains later.

### 1. Extract a headless core and workspace
1. Replace root `Cargo.toml` package with a virtual workspace (`resolver = "3"`, members `crates/dflow`, `crates/dflow-core`, `crates/dflow-tui`, `crates/dflow-gui`, `default-members = ["crates/dflow"]`), retaining root `Cargo.lock` and `target/`. Use Rust edition 2024, version `0.1.0`, license `MIT` for all packages; preserve binary package/bin name `dflow`. Move `src/main.rs` and `src/cli.rs` to `crates/dflow/src/`; move `tests/` into `crates/dflow/tests/` including fixtures, so `CARGO_BIN_EXE_dflow` remains valid. Root `cargo run -- ...` and `cargo test` must still target `dflow`.
2. Move `src/{analysis,git,graph,languages,report}/` and `src/diagram.rs` into `crates/dflow-core/src/` with `lib.rs` exporting those modules. Core dependencies: `git2`, `petgraph`, `serde_json`, `sha2`, `tree-sitter`, `tree-sitter-python`, `tree-sitter-rust`, `toml`; `tempfile` for unit tests. Keep Clap/Crossterm/Ratatui/eframe outside core. Replace binary-owned comparison with `dflow_core::comparison::{Comparison,LocalSelection}`: `Comparison::Local(LocalSelection::{Combined,Staged,Unstaged})` and `Comparison::Branch { base: String, target: String }`. Change `git::capture_comparison(&Comparison, PathBuf, bool)` and `AnalysisSession::report(&Comparison, usize)` and their match arms while preserving JSON `comparison` keys/values. In binary `cli.rs`, keep Clap's `CompareMode::{Local(LocalArgs),Branch(BranchArgs)}` and add `CompareMode::comparison(&self) -> Comparison`; construct it once in main and pass the same selection to capture/report/TUI/GUI. Update core tests constructing old CLI structs to construct `Comparison`; no Clap dependency in core.
3. Expose `report::{AnalysisSession,FocusedNode,FocusedGraph,EdgeContributor}` and `AnalysisSession::focused_graph(&self, usize) -> FocusedGraph` to UI crates; keep existing fields and focused-graph behavior (changed nodes and edge endpoints, shared callers, base/target provenance). Make `diagram::{DiagramFormat,render}` public for binary calls; keep JSON/Mermaid/DOT output unchanged, including main's one trailing newline. Fix moved `include_bytes!`/`include_str!` paths from `crates/dflow-core/src/` to `crates/dflow/tests/fixtures` and preserve report `tool_version` `0.1.0`.

### 2. Extract TUI as a library without changing terminal behavior
4. Move `src/tui/{mod,state,layout,render,watch}.rs` to `crates/dflow-tui/src/` (`mod.rs` becomes `lib.rs`), using dependencies `dflow-core`, `crossterm`, `ratatui`, `notify`, `git2`, `petgraph` and test-only `tempfile`. Replace binary module imports with `dflow_core::{analysis,git,graph,languages,report,comparison}`; replace all CLI mode tests with `Comparison`. Keep `pub fn run(session: AnalysisSession, mode: &Comparison, depth: usize, discovery_dir: PathBuf, include_test: bool) -> io::Result<bool>` and raw-mode guard, local watcher, captured details, statuses and PTY fault hook. Migrate `watch::ReloadWatch::new` and TUI state/render mode matches to the core selection. Headless binary builds must not link terminal dependencies.

### 3. Route optional UIs through the binary
5. In `crates/dflow/Cargo.toml`, use `dflow-core` unconditionally; `dflow-tui`/`dflow-gui` as optional path dependencies; `[features] default = []`, `tui = ["dep:dflow-tui"]`, `gui = ["dep:dflow-gui"]`. Headless binary dependencies are `clap`, `serde_json`, `dflow-core`; binary test dependencies `git2`, `tempfile`. In `cli.rs`, add `AnalyzeOptions::render: Option<RenderTarget>` (`RenderTarget::{Gui,Tui}` via Clap `ValueEnum`), `#[arg(long, value_enum, conflicts_with = "format")]`. Retain `OutputFormat::{Tui,Json,Mermaid,Dot}` as CLI names; `--format tui` is a legacy alias. Select explicit `--render`, then explicit `--format`, then TUI only if `tui` is compiled and both streams are terminals, else JSON. Explicit `--render tui` or `--format tui` needs both stdin/stdout terminals (exit 2 with existing error); unavailable render feature exits 2 with `rebuild with --features tui` or `rebuild with --features gui` guidance; GUI needs no terminal. Keep `--depth`, global `--dir`/`--include-test`, capture failures and completeness exit codes (0/1/2). In `main.rs`, dispatch after one capture/session; gate TUI/GUI calls with `#[cfg(feature = "...")]` so default links neither, and report UI startup errors on stderr without stdout.

### 4. Deliver an interactive native GUI
6. Create `crates/dflow-gui/src/lib.rs` with `pub fn run(session: AnalysisSession, mode: &Comparison, depth: usize) -> Result<bool, eframe::Error>` and dependencies `dflow-core`, `egui_graphs = "0.32"`, `eframe = { version = "0.36", default-features = false, features = ["default_fonts", "glow", "x11", "wayland"] }`, `petgraph = "0.8"`. Save `complete = session.complete()` before `eframe::run_native` and return `Ok(complete)` after normal close. Host `egui_graphs::GraphView<LayoutStateHierarchical, LayoutHierarchical>` with stable widget ID; set its layout state `orientation = LayoutHierarchicalOrientation::LeftRight` before first draw (hierarchical default is TopDown, [source](https://docs.rs/crate/egui_graphs/0.32.0/source/src/layouts/hierarchical/layout.rs?plain=1)). Convert `session.focused_graph(depth)` to a `StableDiGraph` once on construction or depth change, mapping each view ID to widget `NodeIndex` and reverse for selection; iterate sorted IDs and edges. Draw each caller→callee edge once including cycles/shared callers with arrowheads and text status `+ target`, `- base`, `both/base/target`; label nodes with symbol/module title, path, snapshot provenance and added/modified/deleted status independent of color. Prefer target source for shared nodes, base for deleted nodes. Color changed roots green/red/yellow for added/deleted/modified, mixed color for multiple kinds; neutral callers. Enable `SettingsNavigation::with_zoom_and_pan_enabled(true)` and `SettingsInteraction::with_dragging_enabled(true).with_node_selection_enabled(true)`; track selection via graph events. Keep graph state across frames so moved nodes stay moved, and reset layout/fit only on depth change. Use `to_graph_custom` with `Node::set_label`/`set_color`; no handmade canvas.
7. GUI top/status area: show mode/local selection or branch pair, both snapshot identities, depth and complete/partial state plus diagnostics; central graph or explicit empty message; `+`/`-` or depth buttons rebuild focused view. Side details pane on selection: status, snapshot provenance, name/path/range, captured-source excerpt and relevant call-site evidence (including unresolved); display both base and target if present. Read only `session.capture.pair` bytes (mirror TUI `state.rs::node_details`), never live source. On close return original `session.complete()` for exit 0/1; GUI startup failure exits 1. GUI local comparison captures once on launch in this iteration; leave TUI live reload untouched. Empty focused graph still opens to an empty state.

## Verification
- From repo root: `cargo test -p dflow-core`, `cargo test -p dflow-tui`, `cargo test -p dflow --no-default-features`, `cargo test -p dflow --features tui`, `cargo test --workspace --all-features`. Preserve CLI acceptance and PTY validation (`cargo build -p dflow --features tui && python3 scripts/validate_tui_pty.py`; inspect script arguments before running).
- For a temporary Git repository with changed `a.py`, `cargo run -p dflow --no-default-features -- local --format mermaid` emits caller→callee Mermaid, `--format dot` emits Graphviz; `local` emits JSON on piped stdout. `local --render tui` and `local --render gui` exit 2 with feature guidance; `local --render gui --format dot` exits 2. With `tui`, `local --format tui` and `--render tui` start the same TUI only on PTY; with `gui`, `local --render gui` starts a native window even when stdio is redirected, without report stdout.
- Desktop smoke (`DISPLAY` or `WAYLAND_DISPLAY`): temp repo changes `def B(): pass; def A(): B()` to `def C(): pass; def A(): C()`; observe removed A→B and added A→C with arrowheads/status/color, select B/C to inspect captured historical/current source, Ctrl+wheel zoom, background drag pan, node drag move, depth control. Close and check status. Also open clean comparison (empty message, exit 0) and invalid source (partial warning, diagnostics, exit 1). If no native display, use `xvfb-run` if installed for startup/screenshots and report manual interaction as unverified.
- Add GUI projection tests using captured synthetic base/target source: a retargeted call displays exactly A→B (removed/base) and A→C (added/target), labels/provenance remain readable without colors, selecting deleted B shows base source and selecting added C shows target source; cycles/shared callers remain directed without duplicate edges. Add CLI parse/feature tests for `--render gui|tui`, `--format` conflict, default format with and without `tui`, and missing-feature diagnostics. These catch real graph/report/CLI behavior beyond merely constructing a widget.

## Assumptions & contingencies
- User selected egui/eframe + egui_graphs, `--render gui|tui` option (not subcommand), and JSON retained with Mermaid/DOT in default headless build.
- Keep `--format tui` as an alias; default TUI only when compiled with `tui`; GUI never launches implicitly.
- GUI local comparison captures once; live watcher remains TUI-only. Display startup failures return stderr/status 1; do not silently switch backend.
